Documentation

Backend endpoints, data model, and deployment notes.

Architecture

CVE Intel runs on a VPS with FastAPI behind Caddy and Postgres as source of truth. Scrape/news/backup/snapshot/ops-health run via scheduled services. The web UI is static and consumes `/api/*` endpoints.

Primary API Endpoints

GET /api/search?page=1&per_page=50&q=&year=&severity=&kev=
GET /api/cve/{year}?page=1&per_page=200
GET /api/intel/{year}?page=1&per_page=1000
GET /api/intel-summary/{year}
GET /api/intel-stats/{year}
GET /api/cve-detail/{cve_id}
GET /api/news?page=1&per_page=20&tier=&q=
GET /api/ops/freshness
GET /api/health

Data Notes

  • `/api/search` supports optional `q` and server-side pagination.
  • Triage cards should use `/api/intel-stats/{year}` rather than client full scans.
  • Workspace detail should use `/api/cve-detail/{cve_id}` to avoid fan-out calls.
  • News supports tier/query filters and page-based archive loading.

Product Constraints

  • No login system, user accounts, or personalization.
  • No notification bell/avatar UX in app shell.
  • No fabricated data widgets (attack map, fake feed latency sources).
  • All displayed metrics must map to a real endpoint.
